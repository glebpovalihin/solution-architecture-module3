# Паспорт инициативы: Извлекать финансовые показатели из неструктурированных бухгалтерских документов и банковских выписок

## 1. Триаж

- **Вход -> выход:** пакет документов -> структурированные поля
- **Какое действие изменится:** предзаполнение карточки заявки вместо ручного разбора
- **Где именно ML / чем закрыть остальное:** OCR модель; валидация атрибутов и запись - код; подтверждение - специалист
- **Чего не хватает / допущения:** связки документ -> подтвержденные поля исторически не накапливались, потребуется пилот
- **Вердикт:** гибрид

## 2. Постановка

- **Бизнес-цель:** предзаполнение карточки кредитной заявки вместо ручного разбора пакета документов
- **Объект решения:** отдельный документ из пакета документов, детализация до полей докуметнов
- **Входные данные:** несколько видов данных - Excel, PDF-сканы, фото с телефона, выгрузки бухгалтерских систем (текст + таблицы + изображения)
- **Операция:** извлечь сведения - структурированные финансовые показатели  из неструктурированного документа
- **Результат модели:** список полей в JSON: значение + ссылка на фрагмент-источник
- **Результат для бизнеса:** предзаполненная карточка заявки на основе детерминированных валидаций, фильтрации полей без источника
- **Дальнейшее действие:** сотрудник проверяет карточки, правит ошибки и подтверждает - дальше заявка идет по стандартному кредитному процессу.
- **Источник правильного ответа:** подтвержденные сотрудником значения полей + детерминированные проверки. Исторической связки "документ -> подтвержденные поля" нет - накапливается с первого дня пилота.
- **Роль правил и человека:** правила - прием пакета, классификация типа документа, валидация и запись в заявку; человек - подтверждение каждой заявки (решения по кредиту принимает сотрудник); модель - только извлечение полей.
- **Открытые вопросы и предположения:** допустимость обработки документов с банковской тайной и ПДн поручителей требует оценки DPO; доля полей, присутствующих в документах явно
