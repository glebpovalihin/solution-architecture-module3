# ADR-001. Сервис приоритизации ручной проверки подозрительных операций

## Контекст

Финмониторинг (25 сотрудников, ФОТ ~45 млн руб./год) разбирает 10 тыс из 35 тыс помеченных операций в месяц, очередь растет приоритет отдается крупным суммам.
Средний разбор - 12 мин
Из разобранных 4 процента уходят на расследование, большинство расследований являются ошибочными.
Обратная сторона: 600 приостановок в мес, 450 снимаются после разбора, 120 жалоб, часть клиентов уходит.
Разметки "схема/не схема" нет; подтвержденные случаи - единицы с лагом в месяцы.
Проверяемая выборка исторически отобрана правилами - смещение отбора.

## Жесткие ограничения

1. Банковская тайна и ПДн: данные операций не должны покидать контур банка без договора с обработчиком и одобрения DPO
2. Отсутствие полностью автоматических решений, затрагивающих ПДн (блокировка платежа) - участие человека в процессе обязательно.
3. Объяснимость: причина приоритета операции должна быть показана разборщику и воспроизводима для надзора.

## Рассмотренные варианты

| Вариант | Вердикт | Причина |
|---|---|---|
| Классификатор "схема/не схема" с обучением с учителем | Отклонен | Нет эталонной разметки; обучение на эскалациях воспроизводит логику правил |
| Ранжирование без учителя на аномалиях | Отклонен | Нет способа честно измерить качество без контрольной выборки |
| Сервис приоритизации + программа разметки (очередь + вероятностная контрольная выборка) | Выбран | Эффект сразу (качество отбора в фиксированную емкость), разметка накапливается из двух источников без самопроизвольного смещения |
| Обучение на слабых метках (правила + эскалации) | Отклонен | Воспроизводит существующие правила |

## Решение

**Данные:** сервис приоритизации ручной проверки. Разметка накапливается из двух источников: разбор приоритетной очереди по гайдлайну, постоянная вероятностная контрольная выборка, группированная по сегментам и суммам размеченная экспертами.

**Размещение:** self-hosting в облаке (собственный облачный контур банка). Пилот и прод совпадают - стоимость on-prem избыточна для проверки гипотезы. CPU-контур, веса и зависимости только из внутреннего хранилища артефактов.

**Модель:** CatBoost/LightGBM на поведенческих агрегатах + признаки аномальности. Выход - скор приоритета и ранг в очереди, не вердикт

**Архитектура и надежность**: асинхронный пакетный скоринг потока, очередь в интерфейс финмониторинга, фолбэк на текущие пороговые правила при недоступности модели.

## Допущения

1. Эскалация и исход расследования доступны как структурированные поля, а не только в текстах
2. емкость разбора в пилоте не растет - эффект измеряем качеством отбора, а не объемом

## Риски

| Риск | Митигация |
|---|---|
| Модель воспроизводит логику правил | Бейзлайн сравнение с правилами на контрольной выборке; критерий провала - нет uplift >= 20 % |
| Дрейф поведения на новых сегментах, адаптация фрод схем мошенников | Мониторинг распределения признаков, регрессионный набор, триггеры переобучения |
| Регуляторный запрос к объяснимости | топ признаков по каждой операции в интерфейсе разборщика, журналирование версий модели |

## Триггеры пересмотра

1. Накоплено >= 3 000 подтвержденных экспертами меток обоих классов -> пересмотр постановки на классификатор.
2. Uplift против правил < 20 % более двух кварталов подряд -> закрытие ML-части.
3. Выход в новые сегменты клиентов -> внеплановая переоценка.
4. Стоимость контура/инфраструктуры вырастает > 30 % -> пересчет TCO и варианта размещения, релевантности решения.


## Итоговая рекомендация бизнесу

Запустить пилот сервиса приоритизации на 4 месяца: цель - uplift доли эскалаций в разобранном топе >= 1,5x и снижение доли ложных приостановок >= 15 % при неизменной емкости финмониторинга.
