# Паспорт инициативы: Автоматически выявлять подозрительные операции по счетам

## 1. Триаж

- **Вход -> выход:** поток операций -> приоритетная очередь на проверку (транзит, обналичивание, дробление платежей под пороги)
- **Какое действие изменится:** порядок ручного разбора финмониторинга; вердикт и блокировка за человеком
- **Где именно ML / чем закрыть остальное:** ML-ранжирование по поведению; обязательные к разбору правила - кодом
- **Чего не хватает / допущения:** выборка проверок смещена правилами отбора
- **Вердикт:** ML-кандидат

## 2. Постановка

Табличный скоринг + текст назначения платежа; выход модели - скор приоритета и ранг; бизнес-выход - порядок очереди финмониторинга, вердикт и блокировка - за человеком.

- **Бизнес-цель:** изменить порядок ручного разбора помеченных операций, финмониторинг не успевает разбирать все операции - очередь растет; снижение пропуска фрода и ложных приостановок
- **Объект решения:** отдельная операция по счету
- **Входные данные:** строка таблицы операции + поведенческие агрегаты по клиенту за временные окна + текст назначения платежа в свободной форме; вспомогательно могут быть подключены проверки платформы "Знай своего клиента"
- **Операция:** упорядочить варианты - ранжировать операции по приоритету проверки
- **Результат модели:** скор приоритета 0..1, ранг в очереди
- **Результат для бизнеса:** не совпадает с результатом модели - нужна дополнительная обработка: срез топ-k под дневную емкость разбора сотрудниками, детерминированные правила валидации
- **Дальнейшее действие:** сотрудник финмониторинга разбирает операции в порядке очереди и по установленной процедуре решает закрыть или эскалировать на расследование.
- **Источник правильного ответа:** решения сотрудников по приоритетной очереди, зафиксированные по гайдлайну; постоянная вероятностная контрольная выборка из непроверяемой части потока размеченная экспертами; результаты и кейсы пропущенного фрода
- **Роль правил и человека:** правила - расчет признаков, обязательный отбор; человек - все решения, затрагивающие клиента (эскалация, приостановка, отказ в проведении), разметка контрольной выборки
- **Открытые вопросы и предположения:** состав допустимых данных требует участия DPO

## 3. Качество

- Бизнес-метрика: доля эскалаций в разобранном топе очереди 4 % - 400/10000; доля снятых приостановок 450/600 = 75 % ложных; число жалоб 120 в мес
- Метрика модели: Precision и recall при k = дневная емкость разбора примерно 500; PR-AUC на контрольной выборке
- Рабочая точка: срез топ-k под емкость
- Цена ошибок: лишняя приостановка это жалоба и отток

### Шортлист моделей и процедура выбора

Жесткие ограничения: работа в своем облаке, объяснимость признаков, обучение на слабых метках

| Кандидат | Статус | Причина |
|---|---|---|
| LightGBM / CatBoost | В шортлисте | Применим для табличных данных, является общепризнанным решением |
| Логистическая регрессия на ручных признаках | В шортлисте (baseline) | Полностью объяснима, слабое качество |
| LLM для вердикта по операции | Отсечена | Выходной контракт - скор по табличным признакам; LLM нужна только для извлечения признаков из назначения платежа |

Приемочный набор: из сценариев кейса - транзит, обналичивание, дробление под пороги, новые клиенты без истории. 2-3 000 операций из контрольной выборки, размеченных экспертами по гайдлайну (2 независимых сотрудника).

Метрики и пороги:
- Основная: Precision от k и recall в топ-k очереди при k = дневная емкость разбора
- Вспомогательная: PR-AUC на контрольной выборке
- Пороги взяты из экономики: эффект измеряется качеством отбора в фиксированный топ

Провал на сценарии: если модель не вычисляет правила на сценарии "дробление", то модель воспроизводит логику из правил.

Смена решения: если через 2 квартала разметки uplift над правилами < 20 % - закрыть ML, оставить детерминированную перестановку правил

## 4. Данные

| Поле |  |
|---|---|
| Решение | Данные должны поддерживать ранжирование помеченных операций и формирование очереди разбора финмониторинга |
| Объект и гранулярность | Отдельная операция по счету |
| Источник и владелец | История операций за несколько лет банка; владелец - служба финмониторинга |
| Сигнал / источник правильного ответа | Результаты расследования, формально подтвержденные случаи|
| Доступность признаков после запуска | Будут доступны поведенческие агрегаты в разных временных разрезах |
| Разметка | Разборщики финмониторинга по гайдлайнам размечают приоритетную очередь, эксперты размечают контрольную выборку |
| Смещение отбора | метки исторически были получены только для операций отобранных пороговыми правилами и внешними сигналами, об остальном потоке будет известно только через контрольную выборку |
| Репрезентативность | контрольная выборка должна разбиваться по сегментам и суммам чтобы покрыть сегменты без истории проверок и редкие дорогие схемы |
| Объем | Нет нехватки сырых данных, но подтвержденных схем/фрода может быть недостаточно так как есть дефицит разметки |
| Качество | История операций полная, назначение платежа это свободный текст, справочники контрагентов могут требовать нормализации |
| Право на использование | Банковская тайна + ПДн представителей и поручителей, требование к обезличиванию является вопросом к DPO |
| Разрыв и план его устранения | Нет эталонной разметки. Требуется постоянная контрольная выборка органзиуемая со стороны сотрудников финмониторинга |

Вердикт: Gap с планом - инициатива имеет смысл, но сначала этап накопления разметки (предположително от полугода)

## 5. Эксперимент

Развилка по источнику сигнала: подтвержденных случаев мошенничества единицы, для обучения недостаточно.
Путь эксперимента: реализация приоритизации ручной проверки - ранжирование очереди вместо вердикта "схема/не схема"
Но для разбора нужна и контрольная группа, так как разметка только того что извлекла модель порождает новое смещение отбора собственного производства.
Цена пути: 9-12 месяцев накопления разметки до возможного классификатора;
риск заключается в том что модель воспроизведет логику правил.
- A/B невозможен напрямую из-за того что одна очередь.
- Успех: uplift доли эскалаций в топ-500 >= 1,5 раз на данных за N недель.
- Контрольная выборка измеряет, а не обучает.
