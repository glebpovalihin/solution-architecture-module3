# Паспорт инициативы: Прогнозировать нагрузку на кол-центр для планирования смен

## 1. Триаж

- **Вход -> выход:** история звонков -> прогноз по часам
- **Какое действие изменится:** планирование смен по прогнозу
- **Где именно ML / чем закрыть остальное:** ML-прогноз временного ряда; составление смен - код
- **Чего не хватает / допущения:** глубина данных для прогноза
- **Вердикт:** гибрид

## 2. Постановка

Прогноз временного ряда: объем звонков и человеко-часы по почасовым интервалам на горизонт 2-4 недели. Выход модели - прогноз с доверительным интервалом; бизнес-выход - сменное расписание, составленное WFM-планировщиком под прогноз и утвержденное руководителем кол-центра. Источник правильного ответа - фактическая нагрузка из истории звонков, ручная разметка не нужна.

- **Бизнес-цель:** планировать смены по прогнозу уменьшая перерасход ФОТ в простое и срыв SLA в пике.
- **Объект решения:** почасовой агрегирующий интервал работы кол-центра.
- **Входные данные:** строки таблицы - почасовая история звонков (объем, средняя длительность, потерянные вызовы), календарные исключения (праздники, дни зарплат)
- **Операция:** оценить значения: объем звонков и требуемые человеко-часы по каждому интервалу на горизонт 2-4 недели.
- **Результат модели:** прогноз нагрузки по интервалу в числовом выражении.
- **Результат для бизнеса:** требуется дополнительная обработка - перевод прогноза в потребность в штате по сменам
- **Дальнейшее действие:** автоматический планировщик составляет расписание под потребность, руководитель кол-центра утверждает график.
- **Источник правильного ответа:** фактическая нагрузка из истории звонков готовый эталон без ручной разметки
- **Роль правил и человека:** правила - загрузка логов, нормализация рядов,расчет штата; человек - утверждение расписания и ручная корректировка
- **Открытые вопросы и предположения:** учитываются ли смежные каналы (чаты и почта) в той же нагрузке

## 3. Качество

- Бизнес-метрика: SLA ответа за целевое время, доля интервалов с недобором/перебором штата, переработки и простои.
- Метрика модели: покрытие более 90 % интервалов корректным штатом
- Рабочая точка: цена ошибок более критична при недоборе штата, в пиковые часы планирование по верхней границе предполагаемого интервала

### Шортлист моделей и процедура выбора

- Кандидаты: LightGBM на календарных и лаговых признаках (час, день недели, праздники, дни выплат); SARIMA/seasonal-naive с недельной и годовой сезонностью
- Приемочный набор: последние 8 недель истории как холдаут + стресс-периоды (праздники, концы кварталов, дни налоговых платежей).
- Метрика: недобор/перебор смен/сотрудников <= 10 % в 90 % интервалов
- Порог из цены ошибок: недобор может быть дороже простоя - планирование по верхней границе интервала в пиковые часы.
- Провал: недобор/перебор смен/сотрудников хуже стандартного подхода назначения смен -> ML не дает выигрыша; систематический провал на праздниках -> отдельный режим прогноза аномальных дней
- Смена решения: запуск нового канала обращений, смена клиентской базы - внеплановое переобучение

## 5. Эксперимент

- Бектест на последних 8 неделях истории против стандартного механизма подбора, отдельно по праздникам, концам кварталов.
- Пилот 4-6 недель: расписание по прогнозу на одной группе операторов
- Успех: снижение перерасхода/простоя ФОТ группы >= 10 %
